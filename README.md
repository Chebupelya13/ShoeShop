# Информационная система «ShoeShop» (Магазин обуви)

Полнофункциональное настольное приложение (Desktop Application), разработанное в строгом соответствии с требованиями демонстрационного экзамена (ГИА ДЭ КОД 09.02.07-2-2026). Приложение предназначено для автоматизации бизнес-процессов магазина по продаже обуви, включая управление каталогом товаров, учет складских остатков, обработку заказов и контроль доступа сотрудников.

---

## 🛠 Технологический стек
* **Платформа:** C# / .NET 8
* **Тип приложения:** Windows Forms (WinForms)
* **СУБД:** Microsoft SQL Server (T-SQL)
* **Доступ к данным:** ADO.NET (`Microsoft.Data.SqlClient`)
* **Безопасность:** Хэширование паролей по алгоритму SHA-256 (`System.Security.Cryptography.SHA256`)

---

## 👥 Ролевая модель и контроль доступа (RBAC)

В системе реализовано строгое разграничение прав доступа. Функционал динамически адаптируется под текущую роль пользователя:

1. **Гость** (вход без учетной записи по кнопке «Войти как гость»)
   * Только просмотр списка товаров.
   * Панель поиска, фильтрации и сортировки заблокирована.
2. **Клиент** (авторизованный покупатель)
   * Права аналогичны роли «Гость» (в рамках требований демоэкзамена).
3. **Менеджер** 
   * Просмотр каталога товаров.
   * Полный доступ к поиску, фильтрации и сортировке товаров.
   * Доступ к модулю «Заказы» (только режим просмотра списка).
4. **Администратор**
   * Полный доступ к каталогу товаров (CRUD: добавление, редактирование, удаление).
   * Полный доступ к модулю «Заказы» (оформление, редактирование, каскадное удаление).

## 🗄 Структура Базы Данных (3НФ)
База данных нормализована до третьей нормальной формы (3NF) и содержит:

* **Словари:** 
  * `roles` — роли пользователей.
  * `categories` — категории обуви (Кроссовки, Кеды и т.д.).
  * `manufacturers` — производители (Nike, Adidas и т.д.).
  * `suppliers` — поставщики (ООО СпортОпт и т.д.).
  * `order_statuses` — статусы заказа (Новый, В обработке, Доставлен, Отменен).
  * `pickup_points` — адреса пунктов выдачи.
* **Основные сущности:**
  * `users` — учетные данные (логины, хэши паролей, привязка к `roles`).
  * `products` — товары (артикулы, цены, остатки на складе, связи со словарями).
  * `orders` — заказы (дата оформления, сроки доставки, привязка к пункту выдачи и статусу).
  * `order_items` — состав заказа (связующая таблица «многие-ко-многим» между `orders` и `products`).

## 💻 Модули и интерфейс

### 1. Модуль Авторизации (`LoginForm`)
* Защищенный вход по паре логин/пароль с конвертацией пароля в SHA-256 хэш на стороне клиента (в БД уходят и хранятся только хэши).
* Кнопка гостевого входа.
* Валидация полей и обработка ошибок ввода.

### 2. Модуль Товаров (`MainForm` & `ProductEditForm`)
* **Отображение:** Список товаров выводится не стандартной таблицей, а с помощью кастомного UI-компонента (`ProductCard`) внутри `FlowLayoutPanel`.
* **Цветовая индикация (UI/UX):**
  * Если товара нет на складе (`stock_quantity = 0`) — фон карточки становится голубым.
  * Если скидка составляет более 15% — фон становится темно-зеленым, а шрифт контрастно белым.
* **Ценообразование:** При наличии скидки старая цена перечеркивается красным цветом, а рядом выводится актуальная вычисленная цена со скидкой.
* **Поиск и Фильтрация (Мгновенные):**
  * Текстовый поиск (по наименованию, описанию, категории, производителю) работает в реальном времени при вводе текста (`TextChanged`).
  * Комбинируется с выпадающими списками (фильтр по поставщику и сортировка по складским остаткам).
* **Фотографии:** При редактировании товара Администратор может загрузить фото. Изображение масштабируется до 300х200 px и копируется в локальную папку `Images`. При отсутствии фото подгружается дефолтная картинка или генерируется заглушка.
* **Безопасность удаления:** Защита целостности БД — перед удалением товара проверяется таблица составов заказов. Удаление заблокировано, если товар уже куплен.

### 3. Модуль Заказов (`OrdersForm` & `OrderEditForm`)
* Вывод заказов в виде кастомных информационных карточек.
* Оформление нового заказа с указанием пункта выдачи, дат и статуса.
* Подбор товаров в заказ (выбор ID, автоматическое подтягивание наименования из БД, указание количества).
* Транзакционное удаление заказов (с использованием `ON DELETE CASCADE` и `SqlTransaction`).

## 🚀 Установка и запуск (Инструкция)

1. **База данных:**
   * Откройте SQL Server Management Studio (SSMS) или Azure Data Studio.
   * Подключитесь к вашему инстансу (например, `.\SQLEXPRESS` или `(localdb)\MSSQLLocalDB`).
   * Откройте файл `InitDB.sql`, находящийся в корне папки.
   * Выполните скрипт (клавиша `F5`). База `shoeshop` и все таблицы будут созданы и заполнены моковыми данными.

2. **Настройка подключения:**
   * Откройте файл `ShoeShop/DatabaseHelper.cs`.
   * Найдите переменную `ConnectionString` и убедитесь, что параметр `Server=` совпадает с именем вашего локального сервера БД.

3. **Сборка и запуск:**
   * Откройте `ShoeShop.csproj` в Visual Studio 2022 (или выполните команду `dotnet run` в папке проекта).
   * Скомпилируйте проект.
